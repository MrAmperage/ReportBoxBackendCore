# ADR 0002 — Реализация Core

[Базовый ADR](baseline.md) · [Документация Core](../core.md)

Статус: кандидат для review в ветке `Core`; не релиз.

| Решение | Причина |
|---|---|
| `go 1.27.0`, `go.uber.org/fx v1.24.0` | Актуальная стабильная ветка Go и проверенный опубликованный релиз Fx; CI использует последнюю 1.27.x. |
| `New`, `Run`, `NewWithConfig`, `NewWithOverrides` | Разрешение таймаутов до Fx, явное управление конфигурацией без повторной регистрации DI. |
| `lifecycle.Participant` в Fx value group | Одна декларация участника, детерминированный порядок, общий phased shutdown. |
| Один внутренний coordinator, без глобального состояния | Изоляция приложений, возможность проверять lifecycle без Fx. |
| `health.Registry` с последовательными probes, общий бюджет 2s | Нет неограниченных goroutines; required checks влияют на readiness, optional нет. |
| Резерв 20% startup deadline (максимум 5s и StopTimeout) | Время для rollback в общем deadline. |
| `lifecycle.ReportFailure` | Снять readiness и запросить nonzero exit при runtime failure. |
| CI на main/Core и PR в main | Минимальный контроль качества с первого этапа; владелец публикует изменения сам. |

Ограничения: реализация одноразовая, сторонние прямые Fx hooks не получают гарантии координатора. Hooks и checks должны сотрудничать с отменой контекста. Никаких портов или сетевых ресурсов на данном этапе. Полная Go 1.27/Fx проверка и нормализация go.sum через `go mod tidy` необходимы перед merge; локальная среда Go 1.23.2 без доступа к Go proxy позволяет проверять лишь независимые от Fx пакеты. Решения последующих этапов сохраняются открытыми.
