## Текущее состояние

Опубликован `v0.1.0`. Текущая ветка содержит кандидат `v0.1.1` с независимым модулем Static. Тег ещё не опубликован. Go 1.27.4, точные зависимости — в `go.mod`; Static не добавляет сторонних зависимостей.

| Модуль | Состояние реализации |
|---|---|
| Core / Fx / config / logging / lifecycle / health | Реализован |
| RPC server/client | Реализован |
| NATS / JetStream | Реализованы |
| PostgreSQL / GORM | Реализованы |
| Management | Реализован |
| Telemetry | Реализован |
| Static | Реализован, включая Host guard, SPA, root containment, graceful shutdown |

Реализованный модуль не означает подтверждённую готовность к production. Публичные API, defaults и ограничения находятся в профильных документах. ADR содержат действующие решения, не журнал разработки.

## Проверки и блокеры

- В текущей задаче меняется только документация. Повторная сборка не выполняется; требуется финальная проверка Static и всего module graph на Go из `go.mod`.
- Для текущего кандидата сообщалось об успешных изолированных config/handler/Host tests с race detector и vet. Полные тесты Fx, `os.Root`, listener и forced shutdown не подтверждены независимо; требуется запуск на целевом Go toolchain.
- CI workflow отсутствует в опубликованной ветке; результатов Actions нет. Результаты полной интеграции с NATS/PostgreSQL, govulncheck, browser/TLS и нагрузочного тестирования независимо не подтверждены.
- Проверки Markdown: сверка исходной документации с веткой по Git blob SHA, актуализация по публичному API и `go.mod`, проверка относительных ссылок и удаления устаревших ссылок. Исходный код и module graph не меняются.

## Следующие задачи

1. Внести очищенную документацию, удалить заменённые ADR, пройти [release gate](release.md). После подтверждения владельцем слить в `main` и опубликовать `v0.1.1`, не изменяя существующий тег.
2. Разрабатывать ReportBoxAuthenticationService и FrontendService на опубликованном теге; выявленные потребности в инфраструктуре обсуждать отдельно. Не переносить прикладную логику в Core.
3. По мере реальной потребности: контракт Protobuf и его публикация, политика service identity/TLS, migration tooling, outbox/inbox, DLQ и multi-endpoint, расширение Telemetry или Static. Эти функции не являются частью текущего API и не утверждены к реализации заранее.

Текущие ограничения и порядок проверок хранить здесь; не добавлять историю веток, коммитов и старых результатов. Процедура выпуска универсальна; версии и состояние обновлять только по подтверждённым фактам.
